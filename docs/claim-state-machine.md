# 案件集中状态机

案件主流程只有一条：

```text
受理 registered
  → 录入 entering
  → 理算 calculating
  → 审核 reviewing
  → 结案 completed
```

`cancelled` 表示已撤件，是主流程外的终止状态。所有状态名称、允许动作、上一状态、角色动作映射和可编辑范围统一定义在 `src/claims/state-machine.ts`。

## 流转规则

| 当前状态 | 动作 | 下一状态 | 执行模块 |
| --- | --- | --- | --- |
| 受理 | 受理提交 | 录入 | 案件服务 |
| 录入 | 完成理算 | 理算 | 理算服务 |
| 理算 | 提交审核 | 审核 | 案件服务 |
| 审核 | 审核结案 | 结案 | 案件服务 |
| 录入 | 流程回退 | 受理 | 案件服务 |
| 理算 | 理算回退 | 录入 | 理算服务，同时删除理算结果并冲回台账 |
| 审核 | 流程回退 | 理算 | 案件服务 |
| 结案 | 流程回退 | 审核 | 案件服务 |

受理、录入、理算、审核状态允许撤件；结案和已撤件状态不再允许向前提交或撤件。理算或审核状态撤件时，系统先逐级回退、删除理算结果并冲回台账，再从录入状态撤件，禁止绕过理算回退直接改变状态。普通流程回退恢复为进入当前环节时的提交人。理算回退除恢复提交人外，还必须和理算结果删除、累计记录删除、台账冲回处于同一数据库事务中。

每条流转规则同时声明可执行角色：受理环节由受理员处理，录入与理算环节由理算员处理，审核与结案环节由审核员处理；管理员可执行全部流转。API 不只按动作名判断权限，还会结合案件当前状态匹配具体规则。

## 数据锁定

- 受理信息只允许在 `registered` 或 `entering` 修改；受理工作台本身只编辑 `registered`，录入页嵌入的受理信息可在 `entering` 补录。
- 账单、事件录入、疾病信息等理算数据只允许在 `entering` 修改。
- 完成理算进入 `calculating` 后，前端按钮与后端写接口都锁定理算数据；必须先执行理算回退。
- 审核和案件查询页面只读。
- 案件备注是独立追加记录，不覆盖历史备注。

## 并发与审计

状态更新使用“案件 ID + 旧状态”作为更新条件。两个请求同时操作同一案件时，只有一个能成功，另一个返回状态已变化，避免重复提交。每次成功流转都在 `claim_case_transition` 写入原状态、目标状态、操作人、目标处理人、时间和说明；HTTP 操作同时进入统一操作审计。

新增状态或动作时必须：

1. 先修改集中状态机规则；
2. 为合法与非法路径补状态机测试；
3. 若动作包含台账、理算结果等副作用，放在对应业务事务内执行；
4. 不得在控制器或页面中新增直接写状态的分支。
