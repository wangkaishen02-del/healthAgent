# 重启前复盘

这次不是“全部白做”，而是前一版原型解决的是另一类问题。

## 前一版为什么越做越偏

1. 一开始目标不够收敛  
   之前的方向更像“健康险理赔 AI Agent MVP”，同时想做案件受理、理算、审批、结案、规则、LLM 摘要。

2. 先做了理赔流程，没先打稳承保主数据  
   结果就是后面的案件、规则、Agent 都缺少稳定的数据底座，系统边界越来越模糊。

3. 技术路线不统一  
   旧版本是 Python + SQLite + JSON 规则原型；新方向是 TypeScript + Prisma + PostgreSQL + 承保域优先。两套思路天然会打架。

4. 把“验证想法”和“搭正式系统”混在了一起  
   原型适合快速证明可行性，但不适合直接长成正式平台。没有及时切阶段，后续就会觉得很多东西像白做。

## 前一版真正留下来的价值

- 帮我们确认了理赔系统后续会需要哪些域对象
- 帮我们验证了规则、理算、摘要这些能力未来是有位置的
- 帮我们反向确认：正式系统应该先从承保查询做起

## 这次重启后的原则

1. 先只做承保域
2. 先只做查询，不碰理赔受理与自动理算
3. 先统一技术栈，再扩业务域
4. 每一阶段都能单独演示、单独讲清楚

## 当前阶段目标

先完成一个“团体险承保信息查询系统”：

- 保单列表
- 保单详情
- 险种与责任查询
- 被保人查询

等承保域稳定后，再进入配置域、理赔域、Agent 域。
